# Content Security Policy

HTML responses use a fresh 256-bit nonce generated by `middleware.ts`. The
middleware sets the same CSP on the internal request and public response so
Next.js can authorize its framework and hydration scripts. Incoming CSP and
nonce headers are overwritten. Production scripts do not permit `unsafe-inline`
or `unsafe-eval`; `script-src-attr 'none'` also blocks inline event handlers.

`app/layout.tsx` uses request-time rendering because a cached document cannot
reuse a one-time nonce. HTML is private and not cached; versioned Next.js assets
still use immutable caching. The hero remains server-rendered and decorative
JavaScript remains lazy-loaded. Measure hosted performance after deployment,
since server response time can differ from the local production build.

Inline **styles** remain allowed for React style props and GSAP animations.
Development alone allows eval and WebSocket connections for Next.js tooling.
Fonts are served locally by `next/font`. External scripts must receive a nonce
explicitly if introduced later; do not restore `unsafe-inline` to authorize them.

## Verify

1. Build with the normal contact-service environment variables: `npm run build`.
2. Start the production server: `npm start -- --port 3100`.
3. Run `npm run test:csp` (or set `CSP_TEST_URL` to a preview deployment).
4. Check project filters, navigation, and animations in a browser for CSP errors.
5. After deploying, rescan HTTP Observatory and rerun Lighthouse on the live URL.

Tests check nonce uniqueness, matching script attributes, spoofed request headers,
404 responses, and immutable asset caching. A local test does not establish the
deployed Observatory grade.
